# 第一餐流程：廚具設定與推薦診斷

## 問題與修正

- 正式站「我的 → 廚具設定」只讀取既有廚具，空清單時沒有新增入口；「完成設定」只關閉視窗。現改為可新增、直接編輯名稱／類型及容量、取消或明確儲存的表單。
- 儲存沿用受登入保護的 `PUT /api/v1/settings/cookware` 與既有 `replace_cookware` 交易，不新增 migration。保留原廚具的 limitations，寫入後重新讀取資料庫；不修改庫存。
- 空白名稱由契約拒絕；表單阻擋重複名稱，儲存失敗保留草稿以供重試。
- 本機預覽的廚具設定同步更新推薦使用的 onboarding profile，避免畫面與推薦讀取不同清單。
- 重新檢視主廚檔案時，以最新雲端 profile 初始化草稿，避免調整用餐人數時帶入舊廚具。
- 今日頁在庫存、廚具或主廚檔案更新後重抓推薦；空結果依實際篩選原因說明未登記廚具、缺料、數量／單位、已安排菜色或食譜庫缺口，並提供自由搭配入口。
- 「補買前確認」不再被 disabled 屬性阻擋；仍須走原有預覽與確認，不能直接料理缺料食譜。

## 正式資料唯讀診斷（2026-10-19）

- 回報帳號廚具清單為空，主廚檔案保存 1 人份；本次使用者要求 2 人份。
- 庫存已包含葉菜、水果及雞蛋；雞蛋以盒記錄，不能自行換算成顆，葉菜的包也不能自行換算成克。
- 已發布食譜 25 道，補買參考價 25 筆且均已超過有效期。不得修改參考價日期來假裝有效。
- 使用唯讀快照在本機以快煮鍋、電子壓力鍋及 2 人份重算，inventory_only 與 small_purchase 均為 0 道合格食譜：缺少現有食譜所需的主食、蛋白質或調味料，並存在單位待確認項目。補齊廚具不代表現有食材就能滿足食譜庫。
- 不改寫使用者庫存、不放寬過敏硬限制、不捏造料理完成或 AI 成功。第一餐須待使用者確認實際數量、可用調味料及選定料理後繼續。

## 驗證邊界

- 單元／API 測試 191 項通過；新增廚具瀏覽器回歸 3 項通過（空清單新增、編輯後重新整理、庫存不變、取消、重複名稱、失敗重試）。
- 完整 `bun run verify` 通過：191 項單元／API 測試、Web build、API typecheck、30 項瀏覽器測試。Lint 僅有既有 providers.tsx 的 Fast Refresh 警告；瀏覽器使用 MSW，未啟動本機 API，連線檢查曾出現 health proxy ECONNREFUSED，測試全部通過。
- 正式站發布與真實帳號寫入讀回：待驗證。
- iPhone Safari／Android Chrome 真機與實際第一餐料理、庫存扣除、餐份及 EXP：待驗證。
