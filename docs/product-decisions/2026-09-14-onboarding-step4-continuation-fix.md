# Onboarding 第四步繼續與窄螢幕操作列修正

- 日期：2026-09-14
- 分支：`codex/onboarding-step4-fix`
- 基準：`origin/main@95f52ff`
- 狀態：本機完成並通過驗證；尚未推送、合併或部署至 Vercel Production

## 問題

正式站 Onboarding 第四步把「冰箱資料是否完整」與元件初始化時取得的登入布林值綁在同一個 disabled 條件。登入回跳或 session 恢復較慢時，即使使用者已選擇空冰箱，或已輸入食材名稱與期限，「繼續」仍可能保持不可用。底部操作列的主要按鈕使用不可換行文字，在窄螢幕或放大字級下也可能向右溢出。

## 決定與實作

- 「繼續」是否可按只依本步必要資料判斷：確認空箱、已確認 OCR，或完整輸入食材名稱與期限。
- 使用者按下第四步「繼續」時，再向 Supabase 即時確認 session；登入有效才進第五步。
- session 未完成或網路暫時無法確認時，不丟失冰箱草稿，並顯示可操作的登入／重試訊息。
- 登入顯示分成確認中、已登入、未登入三種狀態，避免把等待誤顯示成未登入。
- 底部與 OCR 操作按鈕加入可收縮、換行及最大寬度限制，保留 320px 手機寬度與放大字級下的可用性。

## 驗證邊界

- `bun run verify`：173 tests、Web production build、API typecheck 全數通過。
- Playwright 320 × 700 實走：空冰箱與手動輸入食材兩條路徑都可由第四步進第五步。
- 以 30px 放大按鈕字級壓力測試，底部操作列 `scrollWidth === clientWidth === 320`，無水平溢位。
- 正式站目前仍是修正前版本；登入中的正式帳號、iPhone Safari 與 Android Chrome 要在部署後再次驗證。
