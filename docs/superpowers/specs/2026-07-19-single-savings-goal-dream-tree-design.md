# CooCoo 煮煮：單一存錢目標圓夢樹設計規格

日期：2026-07-19

狀態：設計討論已通過，待使用者審閱書面規格

## 1. 背景與問題

7/17 圓夢看板允許建立、切換及編輯多個夢想，料理與救援成果會直接分配到目前夢想。這個模型同時混合金錢、習慣與健康目標，使使用者不容易回答三個核心問題：

1. 我真正想存錢完成什麼？
2. 我目前還差多少？
3. 依現在的自煮計畫，還要多久才能達成？

新版要移除多夢想分支，以一個進行中的存錢目標作為主線。自煮習慣與健康資產仍會累積，但只作為輔助成果，不與主要目標競爭。

## 2. 產品定位

### 2.1 主要結果

使用者透過自煮降低餐費，將自己確認的金額計入一個明確的存錢目標，並持續看見：

- 此目標目前已存多少。
- 距離目標還差多少。
- 依目前自煮預算與頻率，約還需幾餐、幾週。
- 自煮過程累積的習慣與健康成果。

### 2.2 主從關係

- 主要目標：存錢完成旅遊、緊急預備金、一般儲蓄或自訂用途。
- 核心手段：自煮並降低相對於外食的餐費。
- 輔助成果：自煮習慣、健康自主餐與可追溯健康行動。

新版不提供「養成自煮習慣」與「存錢」兩條平行主線，也不建立非金錢型主要目標。

## 3. 設計原則

- 同一時間只有一個進行中的主要目標。
- 短、中、長期是同一終極目標的累積階段，不是三個夢想或三筆相加的金額。
- 目前已存金額是主要進度的唯一真相；估算節省不得自動視為實際存入。
- 系統先提供自煮預算、階段與時程建議，再由使用者修改及確認。
- 所有節省、營養與達標日期皆標示為估算，不使用「保證省下」或「一定達成」。
- 使用者可以存入 0 元、調低目前已存金額或未達成每週計畫；介面不得責備。
- 健康資產使用可追溯行動，不換算成金錢，也不宣稱醫療效果。
- 舊版多夢想資料不強制轉換，不因改版直接刪除。

## 4. 選定方案與取捨

本設計採用「金額里程碑為主、行為成果為輔」。曾討論但未採用的方案如下：

- 時間里程碑：第一個月、第三個月與最終日期容易受目標期限改動影響，且不能直接表示距離目標金額。
- 行為里程碑：適合習慣養成，但會讓自煮次數取代主要存錢結果。
- 多主線模型：能同時追蹤存錢、習慣與健康，卻會再次產生多夢想切換與成果分配問題。

金額里程碑能直接回答「還差多少」，行為與健康則保留在同一頁的輔助區域。

## 5. 初始設定流程

初始設定採六個步驟，每一步保留返回修改能力，最後確認前不建立目標。

### 5.1 設定夢想

使用者輸入：

- 用途：旅遊、緊急預備金、一般儲蓄或自訂。
- 目標名稱，例如「日本旅行」。
- 目標金額。
- 此目標目前已存金額。
- 目標日期，可選填。

「目前已存金額」必須說明為此目標專用的累積金額，不是銀行帳戶總餘額。

### 5.2 了解外食支出

MVP 收集最近一週：

- 外食餐數。
- 外食總金額。

系統計算平均外食餐費：

```text
平均外食餐費 = 最近一週外食總金額 ÷ 最近一週外食餐數
```

外食餐數為 0 或資料不足時，不執行除法；改由使用者直接輸入一個可接受的「如果這餐外食，通常會花多少」基準。

### 5.3 設定自煮計畫

使用者輸入或調整：

- 每週預計自煮餐數。
- 每餐自煮預算。

系統初始建議：

```text
建議每餐自煮預算 = 平均外食餐費 × 60%
每餐估算節省 = max(0, 平均外食餐費 − 每餐自煮預算)
```

60% 只是可修改的起始建議，不是固定規則。使用者調整任一數值時，預覽立即重算。

### 5.4 預覽達標計畫

```text
剩餘金額 = max(0, 目標金額 − 目前已存金額)
還需自煮餐數 = ceil(剩餘金額 ÷ 每餐估算節省)
預估剩餘週數 = 還需自煮餐數 ÷ 每週預計自煮餐數
```

畫面顯示約略週數；日期顯示為「依目前自煮計畫預估」，不是承諾。

若使用者填寫目標日期，系統另算準時達成所需頻率：

```text
剩餘週數 = max(剩餘天數 ÷ 7, 1 ÷ 7)
每週所需自煮餐數 = ceil(還需自煮餐數 ÷ 剩餘週數)
```

系統比較「每週預計自煮餐數」與「每週所需自煮餐數」，中性提示目前計畫可望提早、接近或晚於目標日期。目標日期已過且尚未完成時，顯示需要調整日期或計畫，不產生負數時程。

### 5.5 產生短、中、長期階段

系統預設建立累積門檻：

- 短期：目標金額的 25%。
- 中期：目標金額的 60%。
- 長期：目標金額的 100%。

短期與中期比例、名稱可修改；長期金額固定等於最終目標金額。驗證規則為：

```text
0% < 短期門檻 < 中期門檻 < 100%
長期門檻 = 100%
```

三個門檻是累積值。例如目標 30,000 元時，預設為 7,500、18,000、30,000 元，不是共需存入 55,500 元。

### 5.6 確認建立

最後一頁顯示目標、目前已存、外食基準、自煮預算、每週頻率、三階段及預估時程。只有使用者確認後才建立主要目標。

## 6. 完成一餐後的成果流程

### 6.1 計算本餐估算節省

完成料理時，系統依序使用：

1. 有完整食材成本時，使用本餐實際用量的估算成本。
2. 資料不足時，使用使用者確認過的每餐自煮預算。

```text
本餐估算節省 = max(0, 外食基準 − 本餐自煮成本)
```

自煮成本高於或等於外食基準時，本餐估算節省顯示 0 元，不顯示負節省；自煮與符合資格的健康成果仍可累積。

### 6.2 使用者確認實際計入金額

系統顯示外食基準、自煮成本與估算節省，接著詢問：「這餐要將多少計入目前目標？」

可選 0 元、估算節省金額或自訂金額。系統不得在未確認時更新主要目標。

若自訂金額高於本餐估算節省：

- 估算節省範圍內記為「自煮相關存入」。
- 超出部分記為「額外存入」。
- 兩者都增加主要目標進度，但只有前者可列入自煮帶來的估算成果。

### 6.3 更新與回饋

確認後同一次操作完成：

- 建立存入紀錄。
- 更新衍生的目前已存金額。
- 更新剩餘金額與階段。
- 重新計算還需自煮餐數及預估週數。
- 更新自煮習慣。
- 依健康確認項目更新健康資產。

同一餐的確認操作必須具備冪等識別，重複點擊或網路重送不得重複增加金額與成果。

## 7. 目前已存金額與紀錄模型

主要畫面允許使用者直接修改「目前已存」。資料層不直接覆寫一個失去來源的總數，而是建立差額調整紀錄。

例如目前由紀錄合計為 12,000 元，使用者修正為 10,000 元時，建立一筆 -2,000 元的調整。這可支援提款、修正輸入或額外資金，同時避免與單餐存入重複計算。

紀錄來源至少包括：

- `meal_deposit`：料理完成後確認的自煮相關存入。
- `extra_deposit`：超過本餐估算節省的額外存入。
- `manual_adjustment`：直接修正目前已存金額產生的差額。
- `opening_balance`：建立目標時輸入的目前已存金額。

```text
目前已存金額 = max(0, 所有有效金額紀錄合計)
```

調低金額是正常情境，不顯示責備文案。若調整後合計小於 0，結果固定為 0，並要求使用者確認輸入。

## 8. 健康資產

### 8.1 定義

健康資產的主值為「累積健康自主餐」，不是金額或抽象分數。只有完成一餐且至少確認一項健康行動時，該餐才增加一次健康自主餐；同一餐最多增加一次。

快速確認項目為：

- 有吃到蔬菜。
- 使用少油料理方式。
- 調味有控制。

食材通過既有食安流程是紀錄健康資產的前提，但不另外增加健康次數。不安全食材不得因勾選健康項目而取得健康資產。

### 8.2 顯示內容

- 累積健康自主餐數。
- 有蔬菜餐數。
- 少油料理餐數。
- 控制調味餐數。
- 每週或連續週達成情況。

系統已有可靠食材及調味資料時，才額外顯示估算減少的鈉或油脂，並提供計算依據。資料不足時不產生營養數字。使用者自填項目要標示為自我紀錄，不作醫療判斷。

## 9. 自煮習慣

自煮習慣與主要金額進度分開計算，包括：

- 累積完成自煮餐數。
- 本週完成餐數／本週計畫餐數。
- 每週達成率。
- 連續達成週數。

實際存入 0 元仍會增加自煮餐數；健康自主餐則依第 8 節資格判定。每週計畫為 0 時不計算達成率，也不將該週視為中斷連續紀錄。

## 10. 單一目標看板

手機版由上到下排列：

### 10.1 主要目標

- 目標名稱與用途。
- 目前已存／目標金額。
- 剩餘金額。
- 依目前計畫還需約幾餐、幾週。
- 編輯目前已存與自煮計畫入口。

### 10.2 單一路徑階段

以一條垂直路徑呈現短期 25%、中期 60%、長期 100%。已完成階段保留完成日期；目前階段突出顯示；不提供夢想輪播、新增分支或切換夢想。

### 10.3 本週自煮計畫

- 本週預計與已完成餐數。
- 下一餐預估可省金額。
- 調整自煮頻率與每餐預算。

### 10.4 輔助成果

- 自煮習慣摘要。
- 健康資產摘要與可展開明細。

主要視覺順序固定為金錢目標、階段、自煮計畫、輔助成果，確保第一眼回答「還差多少、還要煮多久」。393px 寬度不得出現水平溢出。

## 11. 完成與下一個目標

當目前已存金額大於或等於目標金額：

- 剩餘金額固定為 0。
- 目前目標標示完成並記錄完成日期。
- 顯示完成回饋。
- 詢問是否設定下一個存錢目標。
- 提供「設定新目標」與「稍後再說」，不得強迫立即建立。

建立新目標時，舊目標進入唯讀歷史，新的目標成為唯一進行中目標。累積自煮餐數與健康資產是跨目標成果，不隨新目標歸零。

## 12. 無法推算與邊界處理

以下情境不得顯示 `Infinity`、`NaN`、負數週數或虛假的達標日期：

- 目標金額小於或等於 0：阻止建立並提示修正。
- 目前已存大於或等於目標：直接進入完成狀態。
- 每週自煮餐數為 0：顯示尚無自煮速度，請設定頻率。
- 每餐估算節省為 0：顯示目前方案尚未產生可估算的存錢進度。
- 外食餐數為 0：要求直接輸入外食基準，不做除以 0。
- 目標日期已過：顯示逾期並提供調整日期或計畫。
- 自煮成本高於外食基準：估算節省為 0；不影響自煮習慣累積。
- 使用者調低目前已存：接受調整並重算，不顯示失敗或責備。

無法推算時仍顯示剩餘金額，並提供可操作的下一步，不隱藏整個看板。

## 13. 資料模型邊界

本規格描述業務概念，不要求沿用 7/17 的 `dreams` 與 `activeDreamId` 結構。新版至少需要以下獨立概念：

- `SavingsGoal`：用途、名稱、目標金額、可選日期、狀態及階段。
- `GoalAmountEvent`：目標金額的開帳、單餐存入、額外存入及手動調整。
- `CookingPlan`：外食基準、自煮預算及每週預計餐數。
- `CookingOutcome`：單餐成本、估算節省、實際計入金額及冪等識別。
- `HabitProgress`：自煮餐數與每週達成狀態。
- `HealthAssetEvent`：單餐健康行動與來源。

金額以非負整數新台幣儲存；調整事件的差額可以是負數。所有衍生值由純業務規則計算，畫面不得各自實作不同公式。

## 14. 新舊資料處理

- 舊版多夢想、分支與自動成果分配不轉換成新版主要目標。
- 新版使用獨立版本鍵或新版資料結構，第一次進入時執行新的設定流程。
- 舊圓夢資料保留唯讀備份或匯出能力，不在新版主畫面顯示。
- 舊健康數值不搬入新健康資產，因計算定義不同。
- 冰箱、採買與料理等非夢想資料不因本功能改版刪除。
- 新版目標確認後產生的料理成果，才開始累積新版存錢、習慣與健康資料。

若未來搬入 `app_v2` schema，舊 `public` 業務資料仍保持不寫入、不覆蓋；是否提供正式匯入工具需另立規格。

## 15. 明確移除與延後

### 本次移除

- 多夢想輪播與切換。
- 新增夢想分支。
- 健康、體態或習慣作為主要夢想類型。
- 將料理或救援估算金額自動加入目標。
- 把估算節省描述成實際存款。

### 本次延後

- 銀行帳戶串接或自動轉帳。
- 多目標同時進行。
- 舊夢想資料自動轉換。
- 醫療級營養判定。
- 社群比較、排行榜或競賽式健康分數。

## 16. 驗收條件

### 16.1 Domain

- 60% 建議、估算節省、剩餘金額、餐數、週數與日期公式有純函式測試。
- 0 次外食、0 次自煮、0 元節省、逾期日期及超額完成不產生非法數值。
- 短、中、長期門檻只能依序遞增，且長期固定為 100%。
- 同一料理完成請求重送不重複存入或增加健康資產。
- 手動修正目前已存只建立一筆正確差額。

### 16.2 使用流程

1. 新使用者完成六步設定並建立唯一主要目標。
2. 使用者可修改系統建議的自煮預算、頻率及短中期門檻。
3. 完成料理後，系統不會在使用者確認前增加主要目標。
4. 實際計入高於估算節省時，超出部分正確列為額外存入。
5. 存入 0 元仍累積自煮習慣；符合條件時仍累積健康資產。
6. 直接調整目前已存後，剩餘金額、階段、餐數與週數立即重算。
7. 完成目標後可稍後再設定，也可建立下一個唯一主要目標。
8. 第二個目標不會清除第一個目標歷史、總自煮餐數或健康資產。

### 16.3 介面與文案

- 393px 畫面無水平溢出。
- 載入、空白、輸入錯誤與無法推算狀態均有明確畫面。
- 不顯示保證、責備或把估算當實際存款的文案。
- 鍵盤操作、焦點順序、欄位標籤及錯誤關聯可用。
- 主要看板第一屏優先呈現目前已存、剩餘與預估時間。

## 17. 實作範圍建議

此功能適合分成聚焦階段，每階段各自驗證並建立一個 commit：

1. 建立單一目標 domain、計算規則與新版資料邊界。
2. 建立六步初始設定與可修改建議。
3. 以單一路徑看板取代多夢想分支介面。
4. 串接料理完成、實際計入與冪等紀錄。
5. 建立自煮習慣與健康資產累積。
6. 完成目標封存、新目標提示與歷史紀錄。
7. 執行舊資料隔離、行動版與端到端驗收。

詳細檔案、API、測試與 commit 切分需在本規格核准後另寫實作計畫。本規格核准前不修改產品程式。
